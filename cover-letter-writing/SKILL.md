# 자기소개서 작성

지원자의 사실을 유지하면서, 평가자가 빠르게 질문의 답과 직무 적합성을 파악할 수 있는 자기소개서를 만든다. 자기소개서는 서면으로 치르는 1차 면접이라는 관점에서 작성한다.

## 작업 원칙

- 사용자가 제공하지 않은 경험, 수치, 역할, 성과, 회사 사실을 만들지 않는다. 정보가 부족하면 필요한 사실을 짧게 질문하거나 `[확인 필요: ...]`로 표시한다.
- 문항이 묻는 바를 한 문장으로 다시 정의하고, 첫 문장이나 첫 문단에서 결론부터 답한다.
- 채용공고의 직무명·기술명·역량 표현을 의미가 같더라도 임의로 바꾸지 말고 자연스럽게 반영한다. 단순 키워드 나열은 피한다.
- 경험은 상황보다 판단과 행동에 비중을 둔다. 결과는 수치나 관찰 가능한 변화로 입증하고, 근거가 없으면 과장하지 않는다.
- 작성한 내용은 면접에서 본인이 설명할 수 있어야 한다. 초안과 함께 예상 꼬리질문을 제시해 사실 일치 여부를 점검한다.
- "포장"은 사실을 보기 좋게 정리하는 것이지 꾸며내는 것이 아니다.

## 프로젝트 소개·문제해결 경험

프로젝트나 문제해결 경험을 소개할 때는 기술이나 결과물보다 **문제의 발견**을 먼저 분명하게 쓴다.

- 첫 문장에서 일상생활, 업무, 학습, 사용자 관찰 중 어디에서 어떤 불편이나 반복, 오류, 정보 격차를 발견했는지 밝힌다.
- `불편해서 만들었다`로 끝내지 말고, 누가 어떤 상황에서 무엇 때문에 어려움을 겪었는지 설명한다.
- 실제로 겪거나 관찰하지 않은 문제를 그럴듯하게 만들지 않는다. 문제의 출처가 불분명하면 사용자에게 확인하거나 `[확인 필요: 문제를 발견한 계기]`로 남긴다.
- 문제 정의 뒤에는 원인·제약에 대한 판단, 해결 방식, 본인이 직접 구현한 부분, 검증 방법과 결과 순으로 쓴다.
- 기술명은 문제를 해결하기 위해 선택한 이유와 함께 제시한다. 기술 스택만 나열하지 않는다.
- 하나의 항목에는 핵심 문제 하나를 유지한다. 프로젝트 기능 전체를 빠짐없이 설명하려 하지 않는다.

AI·에이전트 프로젝트라면 프레임워크 사용 여부보다 **어떤 업무 문제를 왜 그 방식으로 풀었는지**를 확인한다. 사용자·업무 흐름을 어떻게 파악했는지, 다른 해결 방식과 비교해 무엇을 선택했는지, 실패 사례를 어떻게 평가하고 고쳤는지가 드러나야 한다. AI가 구현을 도왔더라도 지원자가 실제로 결정·검수·검증한 범위를 분명히 쓴다. 해당 경험을 소재로 사용할 때는 [AI 프로젝트 서술·면접 근거 가이드](references/ai-project-evidence.md)를 읽는다.

권장 흐름:

1. **문제 발견:** 일상이나 업무에서 발견한 구체적인 불편과 대상
2. **문제 정의:** 해결해야 할 원인, 제약 또는 실패 기준
3. **해결 판단:** 왜 해당 구조나 기술을 선택했는지
4. **구현과 기여:** 본인이 직접 설계·개발·조정한 부분
5. **검증과 결과:** 테스트, 수치, 배포, 사용자 흐름 등 확인 가능한 증거
6. **직무 연결:** 문항이 요구할 때만 지원 직무와 연결

## 진행 방식

1. 문항, 글자 수, 지원 회사·직무, 채용공고, 활용할 경험과 성과를 확인한다.
2. 채용공고에서 핵심 역할·기술·행동·성과 표현을 뽑고 경험 근거와 대응시킨다.
3. 문항에 맞는 한 줄 결론과 소재를 먼저 제안한다. 소재가 여러 개면 적합성과 증거력을 기준으로 비교한다.
4. 프로젝트·문제해결 경험 항목은 문제 발견 → 문제 정의 → 해결 판단 → 구현과 기여 → 검증과 결과 순으로 쓴다. 그 밖의 문항은 결론 → 필요한 맥락 → 판단과 행동 → 결과/배움 → 직무 연결 순으로 쓴다.
5. 글자 수, 가독성, 사실성, 공고 적합성, 면접 일관성을 검토한다.

문항별 구성과 첨삭 기준이 필요하면 [강의 기반 작성 가이드](references/writing-guide.md)를 읽는다.

## 출력

사용자의 요청에 맞춰 다음 중 필요한 것만 제공한다.

- 문항 의도와 추천 소재
- 글자 수에 맞춘 자기소개서 초안
- 원문을 보존한 첨삭안과 핵심 수정 이유
- 사실 확인이 필요한 부분
- 면접에서 이어질 가능성이 높은 꼬리질문 3~5개

사용자가 완성본만 요청하면 장황한 해설 없이 완성본을 먼저 제시한다.
